# Claude Code 科研工作流手册（忠实拷贝）

> 这是原《流程手册》的忠实拷贝，供想看完整原文的人/agent 使用。本 skill 的可执行精简版见上层 [`../SKILL.md`](../SKILL.md)。手册对原版的刻意偏离（也是流程的一部分）见 [`methodology-adjustments.md`](methodology-adjustments.md)。

> 核心闭环：**发现 idea（第一章） → 实现 idea（第二章）**。
> 贯穿主线：**A2B 分析流程** + **跨领域借鉴**。

```
阶段一：发现 idea                      阶段二：实现 idea
────────────────────                ────────────────────
海量文献                              已发现的 idea
  ① 搭建项目 + Git 分支                 ① 选改进方向（空间大 × 易解决）
  ② 选近两年高引用 baseline             ② A2B 深挖到算子级 → 新现象
  ③ 顶会批量分析（建文档体系）            ③ Claude Code 跨领域检索
  ④ 制造意外实验（Skill 流水线）          ④ 迁移落地：借鉴 B/C → 改造 A → 造条件
  ⑤ A2B 定位根因 + 全景图找突破口         │
      ▼                                 ▼
找到一个具体可突破的问题 ────────────▶ 问题解决、方案落地
```

## 阶段一：发现 idea（从文献中找到具体问题）

### ① 搭建项目结构 + Git 分支管理

目录建议（按需求增删）：

| 目录 | 用途 |
|------|------|
| `source_code/` | 论文开源原码 |
| `pdfs/` / `literature/` | PDF 原文 / 解析后的 MD |
| `analysis/` | 论文笔记、实验报告、对话导出、备选方案、实验输出 |
| `experimental_observations/` | 每次实验的现象与问题 |
| `paper_materials/` | 值得写进论文的现象 |
| `index/` | 全项目文档索引 |
| `decisions/` / `evolution/` / `overview/` | 关键决策 / 宏观规划 |
| `experimental_results/` | 实验详细数据 |

**Git 规则**：主分支只保留经验证有效的干净方案；未验证实验放独立分支；相关文件类型加入忽略规则。→ 保证可溯源、可回滚。

**产出**：一套规整、可复现的项目骨架。

### ② 选 baseline

- 选 **近两年引用量最高**的论文作为 baseline。（*本项目偏离：改为按可复现 × 可对接 × 改进空间验证排序，引用量仅作参考——见 `methodology-adjustments.md` 第 2 条。*）
- 理由：高引用 → 大概率有原码；必有大量论文基于它改进 → 后续"制造意外实验"的素材充足。

### ③ 顶会论文批量分析（建文档体系）

用批量统计代替单篇阅读，沉淀以下文档：

- 创新思路分析 / 完整解题步骤
- 创新类型前景（什么创新能被顶会接收）
- 章节写法规律 / 工作量分析（每篇改了几个模块）
- 所有论文在 baseline 的改进内容 + **baseline 全景图**
- 外部工具应用现状（各领域外部工具解决什么问题）

### ④ 制造意外实验（Skill 流水线）

四步流水线，逐步推进：

1. **MinerU**：论文 PDF → MD 解析
2. **analysis-paper**：分析论文原文 → 结构化论文笔记
3. **deep-read**：批量分析所有论文 → **"问题×现象"交叉矩阵**
   > 核心逻辑：**论文 A 的问题能否被论文 B 的现象解决**，据此组合实验。
4. **squeeze-experiment**：榨干实验数据价值，新现象回写「已发现实验现象」

**产出**：一批意外实验现象。

### ⑤ A2B 分析定位根因 + 全景图找突破口

- 对每个意外现象走 **A2B** 流程（见 [`a2b-rules.md`](a2b-rules.md)），反复多轮，定位现象根因。
- 交叉分析 **baseline 全景图 + 改进点统计**：
  - 改造多的地方 = 问题大，**不等于**没创新空间；
  - 完全没人改的地方 = 可能没问题，也可能**无解**，深入也难找改进。
- 找到**最容易突破**的实验现象，尝试解决。（*本项目偏离：加重要性闸门、杠杆>改造次数、"未改造≠无解"——见 `methodology-adjustments.md` 第 5、7 条。*）

**产出**：一个具体可突破的问题（idea）。

## 阶段二：实现 idea（把跨领域方案迁移到自己领域）

> 符号约定：**A = 自己领域**；B、C = 其他领域。

### ① 选改进方向

按两个互斥因子权衡（结合自身实际）：

| 因子 | 说明 |
|------|------|
| 提升空间 | 该问题是否会有大幅提升 |
| 易解决性 | 该问题是否好解决 |

### ② 建 A2B 文档，深挖到算子级

- 对所选方向建立 A2B 分析文档。
- 不断深挖到**算子（operator）级**问题 → 才会浮现**新的实验现象**。

### ③ Claude Code 跨领域检索

- 基于算子级问题 + 实验现象，让 agent 搜索：**其他领域是否已解决该问题及现象**。
- 用 A2B 流程深入分析相关论文的解决方案 → 明确该方案的**定位**。

### ④ 迁移落地（"造条件"）

1. 查证**领域 C** 是否已用该方案解决其问题；
2. 重点分析**领域 B** 如何应用该方案 → 摸清**生效条件**与解决的问题；
3. 改造**领域 A** 的结构，**创造出该方案生效的条件**。

**产出**：方案在自己领域落地，问题解决。

## 贯穿工具：A2B 分析流程

A = 分析 / B = 沉淀 双轨，四阶段逐步递进。完整细则见 [`a2b-rules.md`](a2b-rules.md)。

**规则**：某阶段数据不理想 → 回退上一阶段重走；对上一阶段几乎完全了解后再进入下一阶段。

## 附：文档产物清单

**必需**：
- 已发现实验现象（`experimental_observations/`）
- 论文素材库（`paper_materials/`）
- 论文笔记（`analysis/`）
- index 全项目文档索引（`index/`）
- 最新实验分析报告 / 单次实验详细报告（`analysis/`）
- version-evolution 关键决策 + 方向调整（`evolution/` + `decisions/`）

- experiment-results 所有实验详细数据（`experimental_results/`）

**可选（批量综合层，阶段一③产出）**：顶会创新思路分析 / 顶会完整解题思路 / 创新类型全景分析 / 章节写法规律汇总 / 工作量分析（每篇改了几个模块）/ baseline 骨架改进内容 / **baseline 骨架全景图** / 外部工具应用现状。

## 附：目录结构对照（示例：原版单仓 vs 一个已有代码仓的两仓拆分）

> 原版手册是单仓（`code/` 与 `paper/` 平级）。若你已有独立代码仓，可拆成两仓。下表为示例映射（替换为你自己的路径）：

| 原版 | 两仓拆分示例 |
|------|--------|
| `papers/`（PDF 存档） | `paper/pdfs/`（忽略） |
| `source/`（fork 基线，只读） | `paper/source_code/<Name>/`（忽略）+ `INDEX.md` |
| `literature/`（MinerU 解析） | `paper/literature/` |
| `code/` + `code/output/` | 你的代码仓（`src/` + `outputs/`） |
| `paper/`（写作） | `paper/manuscript/`（Overleaf 等，忽略） |
| 论文笔记 | `paper/analysis/` |
| 实验报告 / 规划 / 演化 / 论文框架 | `paper/experimental_results/` + `paper_materials/` + `decisions/` + `evolution/` + `overview/` |
