# 方法论修订（对原手册的偏离）

`workflow-manual.md` 是参考，但以下几点刻意偏离。**每条都是流程的一部分，必须遵守。**

1. **按开源状态给可信度打折**。手册信任论文数字，我们不：闭源结果无法复现，只当上界参考（可信度 C，见 [`credibility-tiers.md`](credibility-tiers.md)）。非开源论文的报数不作硬比较锚点，除非自复测。
2. **可复现性优先于引用量**。手册用"高引用"作"有源码 + 多改进"的代理；我们不依赖这个代理，直接按 可复现 × 可对接 × 改进空间 验证排序，引用量仅作参考——也避开最热方向易撞车/被 scoop 的风险。
3. **数据驱动优先，文献驱动其次**。先在自己模型上做 error analysis（哪些样本/模态系统性失败），让真实失败驱动 idea，再用文献解释/解决。纯文献驱动易做出"对文献新、对问题不重要"的工作。
4. **多 baseline 设计视图，非单一全景图**。对照 2–3 个 baseline 的设计选择看设计空间，避免隧道视野。
5. **杠杆 > 改造次数，且"未改造"不等于"无解"**。手册已点明"改造多 = 有大问题但不代表没创新空间"（认同）；需补两点：(1) 改造次数多常因模块好下手（loss/增广/prompt），不等于高杠杆——按对最终指标的敏感度排序；(2) 手册称"完全没改造过 = 大概率无解"未必成立，也可能是未被探索的机会，需单独验证而非默认放弃。
6. **deep-read 交叉矩阵的匹配必须带生效前提**。手册第 2 章④的 B/C 域迁移分析本就强调"生效条件"（认同）；此约束同样适用于阶段一 deep-read 的『问题 × 现象交叉矩阵』：每条『A 的问题 ← B 的现象』匹配须写明生效前提，否则丢弃，避免牵强组合。
7. **重要性闸门**。"最容易突破"≠ 可发表。加一个显著性检查：社区是否在乎，还是只是局部优化。
8. **skill 只取不自造**。具名流水线 skill 从源头获取；查不到就报告并等待，绝不拿自写的冒充。
