# research-pipeline —— 文献 → idea → 落地

> 来源方法论：「Claude Code 做科研」—— A2B 分析 + 跨域借鉴。本 skill **不绑定特定 agent**：指令以工具无关方式描述（"读取某文件""用 `mineru` 解析""写入某路径"），任何能加载本 markdown 的 agent 都可按步执行。
> 完整手册：[`references/workflow-manual.md`](references/workflow-manual.md)。
> 本工作流刻意偏离原手册的 8 条决策：[`references/methodology-adjustments.md`](references/methodology-adjustments.md)——它们是流程的一部分，**必须遵守**。

## 核心闭环

```
阶段一：发现 idea                        阶段二：实现 idea
────────────────────                  ────────────────────
海量文献                                已发现的 idea
  ① 搭项目 + 分支管理                     ① 选改进方向（空间大 × 易解决）
  ② 选可复现 baseline                     ② A2B 深挖到算子级 → 新现象
  ③ 顶会批量分析（建文档体系）              ③ 跨域检索：别的领域是否已解决该算子级问题
  ④ 制造意外实验（4 步流水线）              ④ 迁移落地（造条件）
  ⑤ A2B 定位根因 + 全景图找突破口
      ▼                                     ▼
一个具体可突破的问题 ──────────────────▶ 问题解决、方案落地
```

贯穿主线：**A2B 分析流程**（见末节）+ **跨域借鉴**（A=本领域，B/C=其他领域）。

---

## 阶段一：发现 idea

### ① 搭项目结构 + 分支管理

目录骨架（按需增删）：`source_code/`（论文原码）、`pdfs/`+`literature/`（PDF / 解析后 MD）、`analysis/`（笔记/报告/备选方案）、`experimental_observations/`（每次实验现象）、`paper_materials/`（可入正文素材）、`index/`（文档索引）、`decisions/`+`evolution/`+`overview/`（决策/演化/规划）、`experimental_results/`（详细数据）。

**Git 规则**：主分支只留经验证有效的干净方案；未验证实验放独立分支；大文件/版权内容加忽略。→ 可溯源、可回滚。

### ② 选 baseline

选**可复现 × 可对接 × 改进空间**的论文作 baseline，引用量仅作参考（不依赖"高引用→有源码"的代理，也避开最热方向易撞车的风险——偏离第 2 条）。

### ③ 顶会论文批量分析（建文档体系）

用批量统计代替单篇阅读，沉淀：创新思路/完整解题步骤、创新类型前景、章节写法规律、工作量分析（每篇改了几个模块）、所有论文在 baseline 上的改进点 + **baseline 全景图**、外部工具应用现状。

### ④ 制造意外实验（4 步流水线）

逐步推进：

1. **MinerU**：论文 PDF → MD（CLI `mineru`，非 agent skill，是解析工具）。
2. **analysis-paper**：论文原文 → 结构化笔记（**11 节固定模板**）。这是**唯一独立的子 skill**，见 [`pipeline/analysis-paper/SKILL.md`](pipeline/analysis-paper/SKILL.md)。它产出的 11 节笔记是后续所有批量分析的**唯一输入契约**——deep-read、A2B、全景图都消费它，不要另起格式。
3. **deep-read**（批量过程，见下「deep-read 过程」）：全部笔记 → **"问题×现象"交叉矩阵**。核心逻辑：论文 A 的问题能否被论文 B 的现象解决。
4. **squeeze-experiment**（过程，见下）：榨干自有实验数据价值，新现象回写现象库。

> deep-read 与 squeeze-experiment 是**整库/整批的思考方式**，不是逐文件变换器，故作为本 skill 内联过程描述，不另立独立 skill。

### ⑤ A2B 定位根因 + 全景图找突破口

对每个意外现象走 A2B（见末节），反复多轮定位根因。交叉分析 **全景图 + 改进点统计**：
- 改造多的地方 = 问题大，**不等于**没创新空间；但改造次数多常因模块好下手（loss/增广/prompt），**不等于**高杠杆——按对最终指标的敏感度排序（偏离第 5 条）。
- 完全没人改的地方 = 可能没问题，也可能未被探索的机会，**需单独验证而非默认放弃**（偏离第 5 条）。
- 加**重要性闸门**：最易突破 ≠ 可发表——社区是否在乎（偏离第 7 条）。

**产出**：一个具体可突破的问题（idea）。

## deep-read 过程（批量：问题×现象交叉矩阵）

> 消费 analysis-paper 的 11 节笔记。**保留 analysis-paper 原有能力与产出格式，本过程不改动它，只读它的输出。**

**输入**：一批 analysis-paper 笔记（每篇 11 节）。

**抽取**：
- 每篇的**问题** ← 第 1 节「核心任务」、第 6 节「与本项目关系」。
- 每篇的**现象** ← 第 5 节「实验现象」（已含「适用条件」）、第 4 节关键数字。

**交叉**：遍历「论文 A 的问题 × 论文 B 的现象」，回答——**A 的问题能否被 B 的现象解决？**
- 每条匹配**必须写明生效前提**（数据量/模态/结构/算力前提），否则直接丢弃——禁止牵强组合（偏离第 6 条）。
- 命中即记一条候选「意外组合」实验。

**产出**：一个 `cross-matrix.md`（行=问题，列=现象，格=匹配 + 生效前提），外加候选实验清单。

## squeeze-experiment 过程（榨取自有实验价值）

> 操作化"数据驱动优先"（偏离第 3 条）：先在自己模型上做 error analysis，让真实失败驱动 idea。

**输入**：自有实验日志/结果 + 现象库（`experimental_observations/`）。

**过程**：对每次 run，挖反直觉/系统性失败的现象，量化（具体数字 + 模型），回写现象库。

**产出**：更新后的现象清单 + 由现象驱动的候选 idea。

---

## 阶段二：实现 idea（把跨域方案迁移到本领域）

> A = 本领域；B、C = 其他领域。

1. **选改进方向**：按「提升空间 × 易解决性」两因子权衡（结合自身实际）。
2. **建 A2B 文档，深挖到算子级**：对所选方向建 A2B 分析文档，不断下沉到 **operator 级**——才会浮现新现象。
3. **跨域检索**：基于算子级问题 + 实验现象，检索**其他领域是否已解决该问题及现象**；用 A2B 深入分析相关方案 → 明确其**定位**。
4. **迁移落地（造条件）**：① 查证领域 C 是否已用该方案解决其问题；② 重点分析领域 B 如何应用 → 摸清**生效条件**与所解问题；③ 改造领域 A 结构，**创造该方案生效的条件**。

**产出**：方案在本领域落地，问题解决。

---

## 贯穿：A2B 分析流程

A = 分析 / B = 沉淀，四阶段逐步递进。某阶段数据不理想 → 回退上一阶段重走；对上一阶段几乎完全了解后才进入下一阶段。细则 + 1a–4b + 创新等级 a–d 见 [`references/a2b-rules.md`](references/a2b-rules.md)。

---

## 不可妥协的约束

- **诚实**：严禁臆造引用/数字/结果；不确定标 `[unverified]` 并询问。区分"来源 X 称"与"我的假设"。
- **可信度分级 A/B/C**（每篇报数必标）：A=仓库经核实含可用**代码**（查仓库，不能只看"开源✓"）；B=仅数据公开/代码不全；C=无可用产物。**C 的报数仅作上界参考，不作硬比较锚点**。见 [`references/credibility-tiers.md`](references/credibility-tiers.md)。
- **skill 只取不自造**：具名流水线 skill 从源头获取；取不到就报告并等待，绝不拿自写冒充原版。
- **文档极简**：表格 + 必要说明；无补丁式/重复叙述；文件间分工清晰。

## Checklist

**阶段一**：主分支干净、未验证在独立分支 ｜ baseline 经可复现性而非纯引用量确认 ｜ 批量分析文档齐全（含全景图）｜ 流水线跑完、意外现象已沉淀 ｜ A2B 已定位根因、选中现象已过重要性闸门。

**阶段二**：方向经两因子确认 ｜ A2B 文档到算子级、有新现象 ｜ 已检索到可迁移方案并定位 ｜ 已分析 B/C 生效条件、改造 A 完成落地。
