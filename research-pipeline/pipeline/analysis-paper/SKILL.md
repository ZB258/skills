# analysis-paper —— 论文原文 → 结构化论文笔记

> ⚠️ **重建版，非原版 skill**：本 skill 依据「Claude Code 做科研」流程手册内容重建，**无法对作者原版（私有"9 月资料包"，未公开）校验**。在此基础上打补丁：①可信度分级必填；②闭源结果强制标"上界"；③创新等级改小写 a–d（避免与可信度 A/B/C 字母冲突）；④§5 每条现象补"适用条件"；⑤PDF 优先走 MinerU。按"skill 只取不自造"原则，本文件明确标注为重建版，不冒充原版。
>
> 阶段一④流水线第 2 步。上游：MinerU（PDF→MD）。下游：deep-read（问题×现象交叉矩阵）、A2B 根因分析、跨域迁移、baseline 改进点全景图。
> 笔记**不是读后感**，而是把论文拆成「可被下游批量分析直接消费」的结构化弹药。

## 输入
- 一篇论文的 **MinerU 解析 MD**（首选，含正文/表格/图注/公式），路径由调用方给出。
- 若只有 PDF：**先用 MinerU（CLI `mineru`）解析为 MD**；MinerU 失败再降级到按页读取 PDF，或用 PyMuPDF（`python -c "import fitz; ..."`；按页读取偶尔误报 password-protected）。
- 可选：项目背景（本笔记"与本项目关系"一节参照）。**默认背景 = 调用方给出的项目背景**；无背景时，先问调用方所处领域/任务，或留作通用分析。例：SAR 视觉-语言模型（stage1 视觉-语言对齐 / stage2 captioning，关注 SAR VQA）。

## 输出
- 一个 markdown 文件，**11 节固定结构，节标题一字不差**（保证全项目笔记结构一致，便于人读与批量检索）。
- 中文写作；专有名词、模型名、指标名（BLEU-4 / CIDEr / CLIP / LoRA / mAP 等）保留英文原文。

## 11 节模板（严格按此顺序与标题）

```markdown
# {论文标题}

> 可信度: {A=仓库经核实含可用代码 / B=部分（仅数据或代码不全）/ C=无可用产物（无仓库/空壳/coming soon）/ 综述}　※ 不能只凭论文/笔记写"开源:✓"，须实际查仓库
> ⭐×{N} | 子分类 {①~⑧ 或自定义} | {会议/期刊 年份} | {arXiv id 或 DOI} | 开源：{✓代码/✗/部分}
> 一句话定位：{创新等级 a/b/c/d} ＋ 一句话说清它是什么、强在哪。

## 1. 核心任务
解决什么问题 / 为什么难（尤其在该模态或领域上）/ 任务类型（captioning / VQA / 视觉-语言对齐 / ATR / 基础模型 / 评测基准 / 综述 / 生成）。

## 2. 方法与架构（算子级）
- **整体流程**：输入 → 各阶段 → 输出。
- **关键模块/算子**（下沉到 operator 级）：编码器/解码器结构、注意力变体、损失函数（写出形式）、对齐/匹配策略、数据构造机制、训练范式（预训练-微调/对比学习/指令微调/两阶段迁移…）。
- 不要只写"用了 CLIP"，要写清楚具体怎么用、改了哪个组件。

## 3. 关键贡献
分点列出（1) 2) 3)）。

## 4. 实验结果
数据集 / 评测指标 / 关键数字 / 对比了哪些 baseline / 排名或提升幅度。表格数字尽量原样摘录。
> 若可信度 C：本节顶部加一行 `> ⚠️ 可信度 C：以下数字来自闭源/不可复现来源，仅作上界参考，不作硬比较锚点。`

## 5. 实验现象（供「问题×现象」交叉矩阵）
- 现象1：{观察到的事，含具体数字/模型} → 可能根因：{…} → 适用条件：{在什么模态/规模/结构/数据前提下才成立；迁移到本项目需满足什么}
- 现象2：…
写反直觉的、或别人能用它解自己问题的现象。这是给 deep-read 交叉矩阵（"论文 A 的问题能否被论文 B 的现象解决"）用的弹药，要具体、可被引用，且**每条须写明生效前提**（无前提的牵强组合直接丢弃）。

## 6. 与本项目关系
对当前项目（背景由调用方给出）哪个环节对标；作 baseline / 方法来源 / 数据或评测基准 / 仅背景；是否该复现或对标。

## 7. 可借鉴内容 + 生效条件（供跨域迁移 A2B）
- **可迁移的算子/思路**：…
- **生效前提条件**：数据量/模态/结构/算力要求。
- **移植到我们结构需创造的条件**：…（领域 A 的改造点）

## 8. baseline 改进点（供「改进点统计/baseline 全景图」）
它改进了哪个 baseline 的哪个模块（如：在 X 的 Y 模块上引入 Z）。若本文本身是被改进的 baseline，也写明。

## 9. 优缺点 / 风险
优点 / 缺点 / 复现风险 / 数据可信度。

## 10. 创新等级与定位
a=提出新问题并用新方案解决 / b=新方案解旧问题 / c=套用他人方案 / d=微调；并给一句在本领域地形中的定位。

## 11. 引用与核实
- 信息来源：{MinerU MD 全文 / PDF 全文 / 仅摘要 / …}
- `[待核实]` 条目清单（表格栅格化提不出的 per-cell 数字、作者未公开的代码/venue/license 等，逐条列并注明原因）。
```

## 硬约束
1. **忠于原文，严禁编造**：任何方法/数字/模块名必须来自论文。查不到的写 `[待核实]`，不得臆造。
2. **可信度分级必填且须核实**：标题块第一行 `> 可信度:` 给出 A/B/C（或综述）。**判定 A 前必须实际查仓库确认含可用代码**（不能只看"开源:✓"——很多仓库是空壳 / coming soon / 仅 README）。A=有可用代码；B=仅数据公开或代码不全；C=无可用产物。**C 的所有报数仅作上界参考，不得作为硬比较锚点**，并在第 4 节顶部加 ⚠️ 标注。
3. **创新等级用小写 a/b/c/d**，避免与可信度 A/B/C 字母冲突。
4. **算子级深度**：第 2 节尽量到 operator 级；第 5 节每条现象给出可被交叉利用的具体表述 **及生效前提**。
5. **表格栅格化**：若 MinerU MD 里表格是图片/提不出 per-cell 数字，保留 `[待核实]` 并在第 11 节注明"表格栅格化"，不要瞎填。
6. **来源可溯**：第 11 节必须写清信息来源与 `[待核实]` 清单。
7. **节标题一字不差**，保证全项目笔记结构一致。

## 执行步骤
1. 读取 MinerU MD（或 PDF 经 MinerU 解析）全文。
2. 先判可信度（A/B/C/综述），写入标题块第一行。
3. 按上述 11 节模板填写笔记，覆盖写到目标路径。
4. 自检：11 节齐全、可信度已填、C 级已标上界、创新等级小写、§5 每条现象含生效前提、无臆造数字、`[待核实]` 已在第 11 节列清单。
5. 返回：输出文件路径 + 可信度 + 残留 `[待核实]` 条数 + 一句话定位。
